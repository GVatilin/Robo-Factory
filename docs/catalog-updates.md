# Обновление каталога по п. 3.3

## Управление через сайт

Администратору на странице «Решения» доступна кнопка **Обновить каталог**.

1. **Таблица организатора (CSV)** — загрузка в существующем формате организатора.
   Предварительный просмотр показывает число новых и обновляемых товаров,
   предупреждения и ошибки формата. Кнопка «Применить показанные изменения»
   загружает именно просмотренную версию файла; SHA-256 защищает от подмены между шагами.
2. **Дополнение из источников** — применение подготовленного и проверенного пакета:
   характеристики, ссылки на первоисточники, даты, фотографии, опубликованные цены.
   До записи показываются количества и список изменений по моделям.

Эти действия доступны только администратору, проверяются сервером и записываются
в журнал аудита. Для обычных посетителей и вендоров управление обновлением скрыто.
Ручное добавление/редактирование товара, фотографии, источников, предложений и кейсов
остаётся доступным через существующие формы с разграничением прав производителя.

## Подготовка дополнения

- `datasets/research_round2_*.json` — результаты поиска по всем 188 моделям,
  точные названия производителя и модели, прочитанные страницы и найденные данные.
- `python datasets/prepare_catalog_update.py` скачивает фотографии с этих страниц,
  проверяет формат/размер, делает WebP и листы для просмотра.
- Пакет создаётся в игнорируемой папке `datasets/catalog_update_package`.
- Перед загрузкой оператор проверяет соответствие фотографий моделям. Решения
  сохраняются в `datasets/catalog_image_review.json`: модель, URL, SHA-256 выбранного
  файла, `approved` и причина. Повторная подготовка применяет эти решения только
  при совпадении контрольной суммы; изменившееся фото требует нового просмотра.
  Невыбранные изображения не меняются.
- `bundle.json` и `assets/` размещаются в постоянном каталоге backend
  `/data/uploads/catalog-updates/`. Затем администратор просматривает и применяет пакет.

Импорт не скачивает произвольные URL из HTTP-запроса. Крупные файлы и изображения
живут в volume uploads, JSON-манифесты и программа подготовки — в git. Обновление
кода через GitHub Actions сохраняет каталог и пользовательские проекты.

## Правила качества данных

- Числа приводятся к единицам справочника; у каждого значения есть источник и дата.
- Реальная фотография конкретной модели отделяется от иллюстрации типа оборудования.
  В карточке доступны страница-источник, дата получения и оригинальный файл производителя.
- Импорт не заменяет ручные изменения. Отличающиеся официальные спецификации
  сохраняются как альтернативные публикации для уточнения, не меняя расчёт автоматически.
- Удаление предложения или кейса вручную закрепляет текущую коллекцию за
  администратором: CSV больше не восстанавливает удалённые записи этой коллекции.
  Переименованный товар, который нельзя точно сопоставить с пакетом, пропускается
  с пояснением; остальная часть пакета продолжает обрабатываться.
- Применение пакета не удаляет старые файлы фото, поэтому ранее сохранённые ссылки остаются доступны.
- Цена из открытой публикации хранится отдельным предложением с условиями партии,
  комплектации, НДС и датой. Она не объявляется индивидуальным коммерческим предложением.
- Стоимость ПО, интеграции и обслуживания не приравнивается к нулю, если её не опубликовали.
- Неизвестные характеристики остаются незаполненными. Отсутствие данных не означает
  нулевую характеристику или непригодность продукта.

Планового парсинга сайтов нет: содержимое сайтов может поменяться или относиться к
другой модификации. Пакеты требуют проверки оператором; обновление по запросу
администратора реализовано.
