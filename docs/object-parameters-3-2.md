# Параметры объектов: доработка раздела 3.2

## Добавленные поля

- Склад: `internal_moves_per_day` — внутрискладские перемещения в сутки.
- Медучреждение: `cargo_trips_per_day`, `linen_trips_per_day`, `food_trips_per_day`, `medicine_trips_per_day`, `waste_trips_per_day` — отдельные рейсы для пяти потоков.
- Все шесть полей целочисленные, обязательные, диапазон 0–1 000 000 000. Ноль означает отсутствие потока.
- Начальные значения — явно обозначенные демонстрационные допущения команды. Новые поля автоматически добавляются к справочникам при запуске; значения существующих пользовательских проектов не подменяются.
- Демо-проекты получают примеры с происхождением `team_assumption`. Обычные проекты без новых обязательных значений сохраняются как черновики до заполнения.

## Использование в подборе

Внутрискладской транспорт использует сохранённый суточный поток. Для белья, питания, медикаментов и отходов медицинского учреждения при наличии новых полей используется число рейсов; производительность требуется в рейсах/ч. Килограммы, порции и заявки не приравниваются к рейсам. Старый механизм доступен для данных без полей рейсов. Отдельный общий грузовой поток хранится в проекте; собственного процесса подбора для него в исходном справочнике нет.

## Источники

Форма и экспорт различают данные организатора, допущение команды и нормативный документ. API возвращает идентификатор, тип и URL источника. Демо-датасет не обозначается как норматив. Ссылка открывается из формы; пояснение относится к конкретному полю.

## Административная страница

`/admin/object-references` доступна администраторам через меню «Справочники».

- Создание типа объекта в существующей отрасли.
- Создание источника с категорией, ссылкой и пояснением.
- Создание параметра: раздел, тип, единица, обязательность, значение по умолчанию, диапазон, варианты списка, источник и порядок.
- Редактирование параметров. Код, тип и единица существующего поля неизменяемы, чтобы не переинтерпретировать сохранённые значения.
- Изменение диапазона или вариантов отклоняется, если оно исключает значения существующих проектов.
- Новые определения используются формой, валидацией и шаблонами Excel/CSV без изменения фронтенда.

Расширение справочника само по себе не создаёт расчётную модель для нового типа объекта: процессы и правила подбора настраиваются отдельно.

## Развёртывание

Изменения схемы БД не требуются: используются существующие таблицы справочников и JSON параметров проектов. Docker-сборка включает TypeScript-компиляцию. Автоматический деплой делает резервную копию БД; startup seed добавляет недостающие определения без перезаписи пользовательских значений.
