# Входные параметры объектов — раздел 3.2 ТЗ

## Реализация по пунктам

| Пункт | Реализация |
|---|---|
| 3.2.1 | Отдельные определения для склада, аэропорта, медучреждения. Обязательность хранится в БД; значения каждого проекта независимы. |
| 3.2.2 | Динамическая форма: числа, целые, текст/габариты, логические значения, списки. Разделы, подсказки и переход к незаполненному полю. |
| 3.2.3 | Шаблоны XLSX и CSV для нового и сохранённого проекта, предпросмотр импорта перед применением в форму. |
| 3.2.4 | Серверная проверка кодов, типов, единиц, диапазонов, габаритов, связанных значений; отдельная проверка обязательных полей. Неполный черновик сохраняется, подбор блокируется. |
| 3.2.5 | Значение по умолчанию рядом с полем, источник и допущения раскрываются отдельно. В шаблоне есть default и source. |
| 3.2.6 | Типы и определения полей хранятся в справочниках БД. Администратор может добавлять их через API без изменения формы или схемы БД. |

## Покрытие минимального состава

- Склад: площадь/активная зона/рабочие зоны, смены/дни/часы, приёмка/отбор/отгрузка,
  тип хранения, SKU, масса/габариты паллет, численность/зарплаты/ФОТ,
  производительность отбора, маршрут, свободная площадь и ограничения планировки.
- Аэропорт: тип/зона операции, часы/дни, пассажиры, рейсы/операции/пики,
  маршрут, масса/габариты багажа, персонал, режимные зоны/сертификация,
  работа внутри/снаружи.
- Медучреждение: тип, площадь/этажи, режим, питание/бельё/медикаменты/расходники/
  биоматериалы/отходы, маршруты/лифты, обеззараживание, персонал, СКУД/ограничения доступа.

Справочник после дополнения: склад 45 полей / 25 обязательных;
аэропорт 46 / 23; медучреждение 58 / 22.
Для блока «Зоны и ограничения объекта» заданы демонстрационные значения по умолчанию
с источником «Допущение команды». Кнопка заполнения по умолчанию переносит их в форму.
Существующие пользовательские проекты автоматически не заполняются.
Демо-примеры дополнены явно обозначенными данными команды, пользовательские значения не изменяются.

## Работа с таблицами

В проекте откройте «Загрузить параметры из Excel / CSV», скачайте шаблон нужного формата.
Заполните value. Не меняйте code и unit; единицы должны совпадать с шаблоном
(м² и м2 считаются эквивалентными). Перевод между кг/тоннами и м/мм выполняет пользователь.
XLSX содержит выпадающие списки и ограничения числового ввода; сервер повторно проверяет данные.
Формулы отклоняются: вставляйте готовые значения.

Пустое value очищает поле, удалённая строка оставляет значение формы прежним.
После предпросмотра примените данные и сохраните проект. Незавершённый проект — черновик.
«Проверить параметры» раскрывает разделы с ошибками. Подбор требует заполнения обязательных полей.

## Расширение справочников

Администратору доступна документация `/api/docs` (Authorize с учётной записью администратора).

1. `GET /api/v1/reference/industries` — идентификатор отрасли.
2. `POST /api/v1/reference/facility-types` — code, name, industry_id, description.
3. `GET /api/v1/reference/parameter-sources` — идентификаторы источников.
4. `POST /api/v1/reference/facility-types/{id}/parameters` — code, name, data_type,
   unit, is_required, default_value, min_value/max_value, allowed_values, source_id, source_note.

Форма и шаблоны используют новые определения автоматически после обновления страницы.
Коды уникальны внутри типа, источники обязательны, значение по умолчанию проверяется
по той же схеме, что пользовательский ввод. До 300 параметров на тип объекта.
Добавление процессов и расчётной модели для нового типа — отдельная задача вне раздела 3.2.

## Сохранность данных

`projects.parameters` и `projects.parameter_origins` относятся к конкретной записи проекта.
Определения находятся в `parameter_definitions` с уникальным `(facility_type_id, code)`.
Предпросмотр файла не записывает значения в проект. Сохранение защищено версией updated_at.
Доступ к изменению проекта ограничен владельцем; демо доступно только для просмотра/копирования.
