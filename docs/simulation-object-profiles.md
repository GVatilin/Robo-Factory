# Симуляция объектов — simulation-1.2

Снимок подбора содержит тип объекта, процесс и тип выбранного продукта из каталога. Симуляция сохраняет эти данные вместе с KPI и траекториями. Склад, аэропорт и медучреждение имеют отдельные 3D-сцены; модель робота определяется типом решения из карточки. Для AMR отображаются паллеты, багаж или закрытый медицинский груз. Геометрия и масштаб моделей условные, это не план реального здания.

`POST /projects/{id}/simulations/defaults` возвращает маршрут, скорость, происхождение значений и описание сцены выбранного сценария. Для питания используются `kitchen_to_ward_distance_m`, для отбора `picking_route_length_m`, затем общий `avg_route_length_m`. При отсутствии замеров используются явно подписанные примеры: склад 50 м / 1 м/с; аэропорт 150 м / 1 м/с; больница 60 м / 0,7 м/с. Если максимальная скорость в карточке ниже примера, средняя скорость ограничивается ею. Ручные значения остаются редактируемыми.

Количество, поток, партия, зарядки и посты берутся из выбранного подбора или сохранённой экономики. Не создаются чужие товары или искусственная производительность для украшения сцены. Недостаточная выработка отображается как результат моделирования, а не ошибка программы.

Парк допустим от 1 до 100000 единиц. Событийный расчёт учитывает весь парк, подробные траектории хранятся для первых 60 роботов, 3D показывает первые 18, SVG — до 30. Виджет состояний сообщает размер отображаемой части. Объём и размер партии не укрупняются. Ограничение выполняемой работы — 200000 начатых циклов; большая ожидающая очередь не является причиной отказа. Конфликты движения, санитарная обработка и лифты не моделируются; изображение больницы не подтверждает соблюдение этих требований.

Проверки: `tests/test_simulation.py` (сохранение количества, баланса времени/объёма, профилей, истории, границ), `tests/browser_simulation_objects.py` (реальные локальные копии демопроектов трёх типов, отдельные сцены и типы роботов, запуск/пауза/перезапуск, сохранение, SVG/PNG/JSON, узкий экран). Копии проектов удаляются после проверки.

Существующие сохранённые результаты не переписываются. Для новой сцены старого сценария нужно выполнить новый прогон.
